The brief and the answers

The client asked three questions of an online sales workbook, and wanted separate dashboards plus any insight worth telling.

QuestionAnswerWhere
1. One-time vs recurring customers104 one-time and 116 recurring buyers (52.7% repeat rate). Recurring customers make 76% of gross profit, about 2.8× a one-time buyer each.Page 1 · Customer Retention
2. Total profit by product categoryBeauty ₹76.5 L (27%) leads; Sports ₹59.2 L, Electronics ₹51.6 L, Fashion ₹51.1 L, Home & Kitchen ₹48.1 L. Margins are 25–27%; Electronics is the thinnest.Page 2 · Category Profitability

Beyond the brief

Once the three dashboards were done, the work carried on through a 48-question analysis plan (analysis_questions.md): an 18-check audit (Q1–18), EDA (Q19–36), forecasting (Q37–42) and customer models (Q43–48). Their results feed pages 4 and 5 of the report.

Headline. Sign-ups stopped on 25 Sep 2024. The existing base still grew like-for-like profit 6% in 2025, but new buyers fell 128 → 64 → 28. The customer base is healthy; the funnel is empty.

Profit definition

Agreed before any visual was built, and implemented identically in Power Query and analysis/src/metrics.py:

Net sales  = unit_price × quantity × (1 − item discount) × (1 − order discount)   (excl. tax and shipping)
COGS       = cost_price × quantity
Gross profit = Net sales − COGS          only for revenue orders (not Cancelled / Returned)
Trap. items_total is an order-level value repeated on every line. Summing it overstates sales 4.64×, so the model sums line-level net sales instead.

Power Query fixes

The audit's fixes live in the queries, so every refresh applies them.

Customers: deduplicate and drop stubs

#"Removed blank IDs"     = Table.SelectRows(typed, each [customer_id] <> null and [customer_id] <> ""),
#"Added completeness"    = Table.AddColumn(#"Removed blank IDs", "__filled", each List.NonNullCount(Record.FieldValues(_)), Int64.Type),
#"Sorted by completeness" = Table.Buffer(Table.Sort(#"Added completeness", {{"customer_id", Order.Ascending}, {"__filled", Order.Descending}})),
#"Kept most complete row" = Table.Distinct(#"Sorted by completeness", {"customer_id"}),
#"Removed stub rows"     = Table.SelectRows(#"Removed helper", each not ([email] = null and [join_date] = null and [segment] = null))
Why Table.Buffer. Table.Distinct keeps the first row it sees, but without buffering, Power Query may not keep the sort order. Buffering makes 'most complete row wins' reliable.

Order_Items: fill missing order dates

Group by order_id, take the one date the order's other lines carry, and fill the 23 blanks. Python applies the same fill and flags it (order_date_imputed).

KPI: Profit per Active Customer

One number that ties customer behaviour to profit, and splits into the levers that move it.

Why this KPI

  • It is per customer, so a shrinking or growing base doesn't flatter it the way total profit does.
  • Each factor maps to a team: frequency to CRM, order value to merchandising, margin to pricing.
  • Caveat: winning back a one-time buyer adds profit but can lower PPAC, so the report shows it next to total profit.

Lessons learned

What carried over to the next project (AirlineDataAnalysis-PBI).

  1. Audit before trusting a total. The items_total trap and duplicate IDs would each have produced a confident wrong answer.
  2. Fix data in Power Query, not in visuals. The fix then applies on every refresh and in every measure.
  3. Mirror business rules in one Python module and assert Python = Power BI, so the two never drift.
  4. Pick a KPI that decomposes. PPAC splits into frequency × order value × margin, so a miss points to a team.
  5. Report negative model results. 'Every buyer behaves alike' changed the recommendation from scoring to rules.
  6. Simulate when the question is 'what if'. A customer-level simulation can model sign-ups restarting; a time series can't.
  7. Respect Desktop's rules. M changes with Desktop closed; save, regenerate, then Apply external changes.
  8. Keep personal data out of Git from the first commit, and caveat synthetic-looking data honestly.
